# S12 workflow-runner Skill 需求

> 你现在是一位资深嵌入式开发专家，请帮我编写一个 AI Agent Skill。

## 基本信息

- **Skill 名称**：workflow-runner。
- **Skill 用途**：用图形界面勾选 Skill、填写运行参数并保存为可复用的命名工作流方案；用户在 Agent 对话框输入执行指令后，Agent 按方案顺序调用所选 Skill。
- **触发时机**：用户要新建或修改工作流方案时打开 S12 GUI；用户输入“执行 S12，配置文件：<方案路径>”时触发 Agent 执行。
- **执行模型**：GUI 编辑和保存方案，并只读展示运行进度；Agent 读取方案、记录步骤起止事件并调用 Skill。各 Skill 仍负责自己的执行状态和产物。S12 只保存最小进度与耗时数据，不复制 Skill 的业务结果。
- **界面技术**：首期使用 PyQt6 的 `QMainWindow` 桌面窗口框架，包含菜单栏、状态栏和可扩展的中央工作区；界面样式使用 Qt Style Sheets（QSS）。用 PyInstaller 打包为 Windows exe，放在仓库根目录 `tools/EmbedAI-S12.exe`，与 `EmbedAI-S10.exe` 并列；普通用户双击运行。源码和打包脚本仍分别位于 Skill 目录和 `tools/build_gui.py`，exe 打包时使用的临时目录不纳入版本控制。
- **上游依赖**：各 Skill 的输入及上游产物由 Agent 在执行该 Skill 前检查；未勾选的上游 Skill 不自动补跑。
- **职责边界**：S12 不在 GUI 中执行 Skill，不修改各 Skill 状态，不自动添加未勾选步骤。

## 输入

### 从项目配置读取

GUI 选择项目 `config.json`，按仓库统一规则读取全局和项目配置，显示当前项目及 `project.build_target` 默认目标工程。界面同时提供“项目设置”和“方案参数”两组编辑区：项目设置保存为项目默认值，方案参数只作用于所选工作流。用户不需要手工编辑 JSON。

项目设置至少覆盖下表；字段类型、选项和默认值以 `schemas/config.schema.json` 为准：

| UI 项 | 配置字段 | 保存位置 / 说明 |
|---|---|---|
| 项目名称 | `project.name` | 新增可选字段；现有项目未填写时显示项目目录名；仅作识别名称，不改变目录或平台名 |
| 目标工程 | `project.build_target` | 项目默认目标，App 或 BootLoader；方案中的目标必须与该值一致 |
| 编译器/构建方式 | `project.build_system` | Keil、IAR、GCC Make、GCC CMake、厂家 IDE 或自动推断；界面文案说明此项选择构建系统，编译器可执行文件路径仍由全局 `tool_paths` 提供 |
| 构建配置 | `project.build_config` | 按所选构建方式填写，可留空让 S7b 推断 |
| 串口参数 | `project.serial` | 端口、波特率、数据位、校验位、停止位、编码和读取超时；供 S10 使用 |
| 烧录工具 | `project.flash_tool` | 可选项目默认值，供 S9 使用 |

项目名称已作为可选字段补入项目配置 schema。GUI 的“保存项目设置”只更新项目 `config.json` 中用户实际编辑的字段，保留未知字段及其他 Skill 配置；使用 schema 校验并原子写入。未点击保存时不得改动项目配置。全局 `tool_paths` 先展示当前来源和值，首期只读，避免把机器路径误存到项目配置。S12 由此成为通用模板 `config.json` 只读规则的**明确例外**：仅用户在 GUI 中主动保存项目设置时可写项目配置，Agent 执行方案时仍只读。

**目标工程一致性**：首期以项目 `config.json` 的 `project.build_target` 为唯一执行目标。方案的 `build_target` 是保存时的目标快照，用来检测配置变化，不是单次覆盖。GUI 保存和 Agent 执行时都要求两者一致；不一致时指出两个值，提示用户在项目设置中切换目标后重新保存方案，不得擅自运行到任一目标。这样可避免 UI 显示 App 而现有 Skill 实际操作 BootLoader。

### GUI 输入与交互

| 控件 | 行为 |
|---|---|
| 项目配置 | 选择并显示项目 `config.json` |
| 项目设置 | 编辑项目名称、目标工程、编译方式、构建配置、串口和烧录工具；单独点击“保存项目设置”后写项目配置 |
| 方案选择 | 新建方案，或打开已有方案修改、另存为新方案 |
| 方案名称 | 必填；例如“仅编译”“编译并烧录”；同名保存时明确提示更新该方案 |
| 目标工程 | 默认取 `project.build_target` |
| Skill 列表 | 每行显示编号（如 S1）、完整 Skill 名称、简短用途、实现状态和勾选框；未实现项不可勾选执行 |
| 参数面板 | 显示各 Skill 本次参数、默认值和必填条件；路径参数提供文件或目录选择 |
| 生效值预览 | 对每个已勾选 Skill 显示“项目默认值 → 方案覆盖值 → 执行时生效值”，注明来源；保存前可核对 |
| 执行顺序 | 显示所选步骤的顺序并允许调整 |
| 确定 | 校验并保存当前命名方案，显示路径、执行顺序和“复制执行指令”；不运行 Skill |

未勾选项可保留已填写参数，方便以后再次勾选。每个 Skill 在 UI 中有独立参数区：从项目配置读取默认值，允许填写该 Skill 支持的单次覆盖项，并在界面标明“项目默认值”或“仅此方案”。例如，S10 可在方案里覆盖串口端口和波特率；S7b 的 `rebuild` 可只存在方案里。`project.build_system` 当前由 S7b 从项目配置读取，应通过“项目设置”保存，不能只写进方案后假装生效。没有单次覆盖接口的 Skill 参数也按此处理，必要时在实现 S12 时增加适配接口并测试。界面应提供统一的 QSS 样式文件，至少覆盖 Skill 列表、参数表单、选中与禁用状态、校验提示和保存结果；布局随窗口缩放保持可用。

### 窗口框架、菜单与 Skill 名称

窗口使用标准菜单栏和状态栏，首期至少提供：

| 菜单 | 命令 |
|---|---|
| 文件 | 新建方案、打开方案、保存方案、另存为、选择项目、退出 |
| 工具 | 校验当前方案、复制执行指令；为后续工具入口保留扩展位置 |
| 帮助 | 使用说明、关于；“关于”显示应用名称、版本号及项目位置 |

版本号来自 S12 自身唯一的版本定义，菜单“关于”和发布信息使用同一来源，不在界面中写死多个版本号。状态栏显示当前项目、方案及未保存修改提示。关闭窗口或切换项目/方案前，如有未保存修改，提示保存、放弃或取消切换。

Skill 列表首选“`S1  schematic-reader`”这种编号与全名同屏显示，避免用户必须悬停才能知道含义；旁边可放 `?` 帮助图标，鼠标悬停时显示中文名称、职责和主要输入/输出。键盘聚焦或点击帮助图标也能看到同样说明；名称和帮助内容统一来自 Skill 清单，避免与实际 Skill 目录不一致。方案预览与执行顺序同样显示编号和名称。

### 运行进度与耗时（首期必需）

S12 主窗口提供“运行监控”页：选定方案后可看到该方案的最近运行，显示运行 ID、开始时间、当前 Skill（编号和全名）、每步状态、已完成步骤耗时、当前步骤持续时间及工作流总耗时。窗口按事件更新，无需用户反复刷新；GUI 关闭后重新打开仍可查看本次或历史运行的计时结果。正在运行的步骤采用滚动计时，步骤结束后固定其实际耗时；等待用户操作的时间单独标识，不能混作纯执行耗时。可按步骤查看起止时间和异常摘要，便于比较耗时和调优。

Agent 与独立 GUI 之间使用项目目标工程下的进度事件文件通信。Agent 在运行开始、每个步骤开始、进入/离开等待、步骤结束、运行结束时调用 S12 的轻量进度记录接口；GUI 只读取这些事件并更新显示，仍由 Agent 在对话中实际调用 Skill。即使 GUI 未打开，事件也照常落盘。每次执行生成新的运行 ID，不覆盖旧运行；事件应包含方案路径与摘要、目标工程、步骤 ID/名称、事件类型、主机时间、单调计时值以及可选错误摘要，并遵守 `schemas/progress_event.schema.json`。步骤结束时保存按单调时钟计算的执行耗时和等待耗时；总耗时包含等待时间并单列等待统计。

状态至少区分 `pending`、`running`、`waiting_user`、`done`、`failed`、`skipped`、`unknown`。Agent 调用 Skill 失败时仍须写步骤失败及运行结束事件。运行事件只用于观察，不作为各 Skill 成功状态或产物的权威来源。

**进度事件规则**：同一项目、同一目标工程一次只允许一个未结束的 S12 运行，以免多个工作流同时修改同一 `state.json` 或工程文件。开始时建立带运行 ID 的活动标记；发现已有运行时，先检查其状态，不能自动覆盖。每个运行的事件含连续序号、运行 ID、步骤 ID、事件类型、ISO 8601 主机时间和单调计时值；只在该运行目录内追加写入，完整一行写入并 flush。步骤事件至少有 `step_started`、`wait_started`、`wait_ended`、`step_finished`；运行事件至少有 `run_started`、`heartbeat`、`run_finished`。每个开始事件只允许一个相应结束事件；重复结束、乱序或损坏记录由 GUI 标明数据异常，不自行补造成功结果。

**计时口径**：步骤总耗时从 `step_started` 到 `step_finished`，包括该 Skill 的准备、Agent 处理、工具执行、验证和人工等待；人工等待从 `wait_started` 到 `wait_ended` 单独累加。步骤执行耗时 = 步骤总耗时 − 人工等待耗时；工作流总耗时从 `run_started` 到 `run_finished`，包含各步之间的停顿。完成时由进度接口用同一台主机的单调时钟计算并保存秒数，GUI 可显示到 0.1 秒；不同运行的比较使用已完成记录的固定值，不用墙上时钟差计算。当前步骤滚动计时仅是实时估计，结束值以记录值为准。

**活跃与中断**：进度接口在步骤边界及执行期间至少每 30 秒写心跳；长时间运行的外部命令由调用包装层维持心跳，人工等待由等待流程维持心跳。若 Agent 自身工作无法保证周期心跳，UI 应显示“最后更新于…”并把实时计时标为估计值。超过 90 秒没有新事件时，GUI 显示“连接状态待核实”，暂停把滚动时间称作执行耗时；不能仅因超时写 `failed` 或 `run_finished`。重新收到事件后恢复；用户或 Agent核实运行已中断后将显示状态置为 `unknown`，保留原始事件和已完成步骤的耗时。活动标记只能在运行正常结束或明确核实中断后收口；新运行不能静默抢占。

### 参数映射与生效值

`references/skill_parameters.md` 是 UI 字段清单与执行适配的唯一依据。**每个可编辑项**至少记录：Skill 编号、UI 标签、项目配置键及默认值、方案 `params` 键、类型与约束、值的优先级、实际 Skill 读取入口（CLI 参数、GUI 预填、项目配置或 Agent 输入）、是否支持单次覆盖、校验方式。新增 UI 字段时必须先补映射和执行适配；没有可靠传递路径的字段只读展示，不能提供看似可用的输入框。

首期映射至少覆盖项目名称、目标工程、构建方式与配置、S7b `rebuild`、S9 烧录工具、S10 串口端口/波特率/数据位/校验位/停止位/编码，以及所选 Skill 的必填输入。示例：

| UI 字段 | 项目默认值 | 方案覆盖 | Skill 实际入口 |
|---|---|---|---|
| 构建方式 | `project.build_system` | 首期不支持 | S7b 读取项目配置 |
| 重新编译 | 无 | `S7b.params.rebuild` | S7b `build.py --rebuild` |
| 串口波特率 | `project.serial.baudrate` | `S10.params.baudrate` | S10 CLI `--baudrate`，或 S10 GUI 启动时预填 |

预览按“方案覆盖值（若该项支持且已填写）→ 项目配置值 → Skill 自身默认值”的优先级计算，并明确标注来源。预览结果要与执行适配使用同一套解析逻辑；项目配置改变后，重新打开方案或执行方案时重新计算，不使用保存方案时显示过的旧预览。只有当配置值确实可以传入该 Skill 时，预览才将其称为“生效值”。

S10 保持现有 GUI 为普通用户入口。若方案配置 S10 单次串口覆盖项，S12/Agent 需要提供 S10 GUI 启动预填机制，并保证用户在 S10 窗口仍可检查和修改参数；此适配实现并验证前，不能声称 GUI 路径会应用覆盖值。高级 CLI 路径可使用 S10 现有的 `--port`、`--baudrate` 等参数。`read_timeout_ms` 当前没有 S10 CLI 单次覆盖入口，首期只作为项目默认值编辑，除非后续补齐适配。

### Agent 输入

Agent 在创建项目工作区时已指定项目路径；S12 从当前项目定位 `config.json` 和该项目的 `workflows/` 方案。GUI 保存后提供可复制的指令：

```text
执行 S12，配置文件：<方案文件的绝对路径>
```

如果当前项目只有一个可执行方案，用户可以只输入“执行 S12”，Agent 自动使用该方案；有多个方案时应列出名称让用户指定。用户也可使用 GUI 复制的绝对方案路径指令。指定路径必须属于当前 Agent 项目；不一致时先指出项目路径冲突，不跨项目猜测。

## 输出

### 写入 state.json

**无。**S12 不写 `state.s12`，也不改写其他 Skill 的字段。通用模板的 state 输出要求在此由方案文件替代，因为保存方案不是一次工作流运行；各 Skill 的运行结果由各自写入。

### 写入工作流方案

每个方案保存在项目根目录的 `workflows/<方案文件名>.json`。同一项目可有多个方案；保存时仅更新选定方案，其余方案保持不变。先校验再原子替换，避免半写文件。方案只保存选择与单次参数，不复制项目默认配置或运行结果。项目设置与方案各有独立保存动作，界面清楚提示尚未保存的修改。

```json
{
  "schema_version": "1.0",
  "name": "编译并烧录",
  "project_config": "../config.json",
  "build_target": "App",
  "steps": [
    {"id": "S7b", "skill": "build", "enabled": true, "params": {"rebuild": false}},
    {"id": "S9", "skill": "flash", "enabled": true, "params": {}}
  ]
}
```

`steps` 数组顺序就是执行顺序；`enabled=false` 的步骤不运行，但参数可保存。方案中的相对路径相对方案目录解析；复制给 Agent 的指令使用方案绝对路径。`schemas/workflow.schema.json` 约束版本、项目路径、目标工程、Skill ID 与名称、重复步骤、参数类型及已勾选项的必填参数。GUI 保存前和 Agent 执行前均校验。`input.schema.json` 约束入口输入；`output.schema.json` 约束方案保存与进度输出的指针和统计，不约束 state 字段；`progress_event.schema.json` 约束事件。

方案只保存单次覆盖值和选择，不冻结项目默认值。保存方案时记录所依赖项目配置字段的摘要或值快照，用于检测后续变化；该快照仅作提示，绝不当作执行参数。再次打开方案或 Agent 执行时，若相关项目默认值已变，展示变化的字段、旧值和当前值，并以当前项目配置重新计算生效值。与执行无关的项目字段变化不触发提示。

### 写入 outputs/

每次执行写入 `<项目根>/<build_target>/outputs/s12/<run_id>/events.jsonl`，保存最小进度事件及计时；可另写由事件派生的 `timing.json` 方便 GUI 和用户查看每步耗时。事件追加写入并及时刷新，GUI 只读，不修改历史事件。目录按运行 ID 分开，避免多次执行覆盖。S12 不复制各 Skill 的报告或产物；命名方案仍保存在项目根 `workflows/`，不属于运行输出。`state.json` 继续不写 `state.s12`。

## Skill 目录结构

```text
skills/workflow-runner/
├── SKILL.md
├── schemas/
│   ├── input.schema.json
│   ├── output.schema.json
│   ├── workflow.schema.json
│   └── progress_event.schema.json
├── scripts/
│   ├── start_s12.pyw
│   ├── gui.py
│   ├── config_service.py
│   └── progress.py
├── references/
│   └── skill_parameters.md
└── assets/
    ├── workflow_example.json
    └── theme.qss
```

`config_service.py` 负责方案读写、校验、生效值解析和项目配置变更检测；`progress.py` 提供 Agent 调用的运行／步骤起止、等待和心跳记录接口，并计算耗时；`gui.py` 使用 PyQt6 的 `QMainWindow` 构建窗口、菜单栏、状态栏和运行监控页，并加载 `theme.qss`。`references/skill_parameters.md` 记录各 Skill 参数映射。文件名可在实现时调整，保留模板规定的目录职责。GUI 启动时若 PyQt6 或样式文件不可用，应显示可操作的错误信息，不能静默退出。

## 执行步骤

### GUI 保存方案

1. 读取项目 `config.json` 和选中的现有方案；新建方案时使用项目默认值。
2. 用户可在“项目设置”编辑通用字段并单独保存；GUI 校验并仅更新这些字段。
3. 用户勾选 Skill、填写该 Skill 的方案参数、调整顺序并输入方案名称。
4. 按参数映射表计算并显示各步骤生效值；校验静态配置和所选步骤。已勾选未实现 Skill、必填参数缺失、参数无法实际传给 Skill，或项目设置有未保存修改时提示并阻止保存方案。
5. 在项目 `workflows/` 中保存当前命名方案；不改写其他方案或 state。
6. 显示方案路径、执行顺序和可复制的“执行 S12，配置文件：…”指令。

### Agent 执行方案

1. 从当前 Agent 项目定位项目配置及用户指定的方案并校验；确认方案 `build_target` 与项目 `project.build_target` 一致；检测其他项目默认值变化并以当前值重新计算执行参数。
2. 创建本次运行 ID 和进度事件文件，记录运行开始；GUI 可据方案路径发现并展示这次运行。
3. 按 `steps` 顺序只处理 `enabled=true` 的项。每步调用前记录开始事件；检查输入、调用对应 Skill 的 `SKILL.md` 和脚本，等待该 Skill 自己的操作与校验完成。S10 等人工操作进入等待时记录等待事件。
4. 每步结束记录结果和耗时，工作流结束记录总耗时。某步失败或缺输入时记录失败并停止后续步骤；未执行的步骤保留 `pending`，只有明确跳过才标记 `skipped`。再次执行生成新运行 ID，各 Skill 依据自身契约判断复用或重跑。

Agent 不因 S11 日志现象自动添加修复步骤。若用户在对话中明确调整本次范围，以最新指令为准，并说明实际执行范围。

## 依赖

- Python 3.10+；首期 GUI 依赖 PyQt6，样式使用随 Skill 分发的 QSS 文件。安装说明和版本约束在实现时写入项目依赖文件及 S12 使用说明。
- JSON Schema 校验沿用仓库现有 `jsonschema` 依赖。
- 工具链、硬件和其他第三方依赖由各 Skill 自身检查。

## 禁止事项

- 不在点击“确定”时启动 Skill、烧录或采集。
- 除用户在 GUI 中主动点击“保存项目设置”外，不修改项目 `config.json`；不修改其他 Skill 的 state 字段或产物。
- 不运行未勾选 Skill，不自动修复或无限重试。
- 不因保存一个方案覆盖项目中的其他命名方案。

## 与现有仓库衔接及验收

`workflows/stm32_full_flow.json` 是旧的全流程目标态示例，包含未实现的 S6，且把 build 写作 S7；不能直接作为首期命名方案。实现时提供符合上述 schema 的示例，将 build 编号统一为 S7b，并更新 README 中的 S12 描述。

1. 保存“仅编译”和“编译并烧录”后，两份方案均存在；修改前者不影响后者。
2. 点击“确定”只生成方案和复制指令；Agent 收到指令后才执行。
3. 执行“仅编译”只调用 S7b；执行“编译并烧录”按顺序调用 S7b、S9。
4. 取消 S9 后，即使编译产物存在也不烧录。
5. 步骤缺输入或失败时停在该步；各 Skill 自己保存状态和产物。
6. 用户在 S12 UI 保存项目名称、构建方式和 S10 串口默认参数后，重新打开界面仍能看到这些值；保存“仅编译”方案不覆盖这些项目设置。
7. 在方案中单次覆盖 S10 波特率时，仅该方案执行使用覆盖值，项目串口默认值保持不变。
8. 修改项目默认构建方式后重新打开旧方案，UI 显示旧值、当前值及重新计算的 S7b 生效值；Agent 执行时也读取当前值。
9. 在 S10 方案中设置临时端口或波特率后，启动 S10 GUI 能看到预填值；若预填机制未实现，UI 不开放该覆盖项。
10. 对每个开放的 UI 参数验证“保存方案 → Agent 读取 → Skill 实际收到相同值”；映射表中无执行入口的字段不得作为可编辑参数出现。
11. 主窗口包含文件、工具、帮助菜单及状态栏；“关于”显示与发布信息一致的版本号；有未保存修改时切换方案会提示。
12. Skill 行、顺序预览均显示编号和全名；鼠标悬停、键盘聚焦或点击帮助图标可查看同一份用途说明。
13. Agent 执行长工作流时，GUI 无需刷新即可显示当前 Skill、已完成步骤耗时和滚动的当前/总耗时；关闭并重开 GUI 后历史计时仍可查。
14. S10 等人工等待环节的等待时长单独统计；执行失败或正常结束均写入结束事件；异常中断无结束事件时显示状态未知和最后更新时间。
15. 连续运行同一方案两次产生不同运行 ID，监控页可选择查看并比较两次各步骤耗时，旧运行记录不被覆盖。
16. 项目目标从 App 改为 BootLoader 后，原 App 方案保存和执行均被阻止，并明确显示冲突值；重新保存为 BootLoader 方案后才允许执行。
17. 同一项目目标已有未结束运行时，第二次执行被拒绝并显示现有运行 ID；不会并发写同一目标的 state 或输出。
18. 一次步骤包含准备 10 秒、实际执行 20 秒、人工等待 30 秒、验证 5 秒时，步骤总耗时约 65 秒、等待约 30 秒、执行约 35 秒；工作流总耗时还包含步骤间停顿。
19. 长步骤持续产生心跳时 GUI 保持运行显示；超过 90 秒无事件时仅显示状态待核实，不把步骤记为失败。重新收到事件后更新计时；确认中断后显示 `unknown`。
