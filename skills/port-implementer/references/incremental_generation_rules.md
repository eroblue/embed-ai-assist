# 增量生成规则（S5c Agent 定点修改实现代码的行为约束）

> 适用范围：`port_diffs/<单元>_diff.json` 中 `generation_mode=incremental` 的单元。
> 核心红线（requirement 原文）：**Agent 无权重写整个文件，它只做定点修改。**
> 这一页是防止"每次接口小改动都全文件重写、适配代码面目全非"的关键防线。

## 一、输入

| 材料 | 位置 | 用途 |
|---|---|---|
| 现有实现 | `Drivers/Port/Src/port_impl_<外设>_<平台>.c`（上轮产物） | 修改基底，**原样保留未涉及部分** |
| 变更点 | `outputs/s5c/port_diffs/<单元>_diff.json` | `changes` 明细（interface_added/removed/modified 等） |
| 接口契约 | `Drivers/Port/Inc/<外设>_port.h` + manifest 接口清单 | 修改后签名须与之一字不差 |

## 二、定点修改原则

1. **只动 diff 要求的对应物**：`changes` 里没有的接口/实例，一行都不碰
   （包括"顺手优化格式"、"补个注释"——格式化需求应作为独立变更单独一轮）。
2. **保留文件头注释与既有结构**：文件头"逻辑实例映射"说明、`static` 上下文数组、
   错误码映射等是下一轮人工对照的锚点，修改时同步更新、不得删除。
3. **接口新增 → 只加不重构**：按 `changes.type=interface_added` 在对应位置补函数实现
   （含必要的 ctx 字段），不动其他函数；新函数遵守 `port_impl_pattern.md` 骨架。
4. **接口删除 → 删干净**：删函数体 + 相关 ctx 字段，grep 该函数名确认实现文件内
   无残留引用（头文件由 S5b 负责，本层不改 `*_port.h`）。
5. **接口签名变更 → 只改签名与受影响逻辑**：参数/返回值变化时同步更新实现内
   的参数校验与错误码分支，不重排无关代码。
6. **行数自律**：每个变更点预期 ≤ 15 行代码改动；自感要写超 → 先怀疑判定错了
   （或应走 full），不是"这条改动比较特殊"。

## 三、diff 范围校验（`diff_range_checker.py`，生成后必跑）

| 指标 | 阈值 | 判定 |
|---|---|---|
| 新增行数 | > 变更点数 × 15 × 3 | 异常（added_overflow） |
| 删除行数 | ≥ 基线行数 80% 且预期变更量 < 基线行数 | 异常（rewrite，整文件重写特征） |
| 无关行改动 | 应为 0 | （空行差异不计；异常即越界修改） |
| 实现文件缺失 | incremental 单元找不到对应 `.c` | 异常（missing，增量要求文件已存在） |

- 基线：prepare 段镜像的 `outputs/s5c/code_baseline/`（上轮产物副本 + sha256 索引）。
- 正常 → `outputs/s5c/diff_check_result.json`；异常 → `outputs/s5c/diff_anomaly.json`
  + `state.s5c.status=error`，当前文件**保留现状**（不回滚、不覆盖，上轮内容在
  `code_baseline/` 可对照）。
- validate 段也会复跑该校验（异常计入产物错误，退出码 1）。

## 四、异常后的处置流程

1. Agent **不得自行"修复后继续"**——先向用户报告 `diff_anomaly.json` 内容。
2. 用户二选一：
   - **定点修复**：Agent 对照 `code_baseline/` 恢复越界改动，重新做最小修改；
   - **转全量**：用户确认本次确实是大改动 → 该单元应走 `full`（说明判定阈值需
     复核，或本次变更确实超 60%）→ 重跑 prepare 后按 full 全量生成该文件。
3. 处置完成后重跑 `diff_range_checker.py` 直到通过，再进 validate 终验。

## 五、skip 单元（同样重要）

`skip` 单元的代码文件**一个字符都不改**——含两类：

- 接口未变（正常 skip）；
- **用户手改且接口未变**（漂移标注）：文件由用户维护，Agent 不得"顺手同步接口"
  或"统一格式"。若用户希望恢复自动生成，**删除该文件**即可（下轮 prepare 判 full）。

重跑 skip 单元的常见借口（"顺便统一格式"、"补个注释"、"顺手同步新接口"）全部无效。

## 六、自检清单（每个 incremental 单元改完）

- [ ] `changes` 里每类条目都有对应代码动作，无遗漏、无多余。
- [ ] 文件头注释与既有结构保留/更新（锚点未丢）。
- [ ] 新增接口签名与 `*_port.h` / manifest 一字不差；未改任何 `*_port.h`。
- [ ] 删除接口后 grep 实现文件内无残留引用。
- [ ] ISR 相关回调改动仍满足判空硬约束（`isr_safety_rules.md`）。
- [ ] 预估行数在 变更点 × 15 内；超了先自查判定是否应为 full。
