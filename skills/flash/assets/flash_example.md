# S9 flash 使用示例（jlink CLI 机制，一期）

以本仓库 `examples/stm32f103zet6`（STM32F103ZET6，Keil 工程，s7b 已 done）为例。

## 0. 前置配置

项目级 `examples/stm32f103zet6/config.json`（project 段）：

```json
{
  "project": {
    "build_target": "App",
    "flash_tool": "jlink",
    "flash_offset": 0
  }
}
```

> 说明：本工程 uvoptx 的 `<pMon>` 为 `STLink\ST-LINKIII-KEIL_SWO.dll`（ST-Link 证据），
> 但实际探针为 J-Link——智能推断会因 `stlink_cli` 未安装报错（不猜），
> 故**显式配置 `flash_tool = "jlink"`**。

全局 `config.json`（tool_paths 段，二选一）：

```json
{
  "tool_paths": {
    "jflash": "C:/Program Files/SEGGER/JLink/JFlash.exe"
  }
}
```

> 未配置 `jlink` 键时，S9 从 `jflash` 同目录自动探测 `JLink.exe`。

## 1. prepare（就绪检查 + release 发布 + jlink 脚本生成）

```bash
python skills/flash/scripts/prepare.py --config examples/stm32f103zet6/config.json
```

产物：

```
examples/stm32f103zet6/
├── App/outputs/s9/generation_brief.md   # 任务书（烧录信息清单）
└── release/                              # 发布目录（项目根，S9 唯一写者）
    ├── Template.hex                      # s7b 产物副本（hex 优先，自带地址）
    ├── Template.bin                      # bin 副本（同发布，烧录用 hex）
    └── flash_cmd.jlink                   # 自包含复烧脚本
```

`release/flash_cmd.jlink` 内容示例：

```
# Generated by S9 flash（prepare/flash 生成，每次运行按当前选项覆盖）
# device: STM32F103ZE   interface: SWD
# 在 release/ 目录下执行：JLink.exe -device <device> -if <IF> -speed 4000 -autoconnect 1 -CommandFile flash_cmd.jlink
loadfile Template.hex
verify
r
g
qc
```

## 2. flash（执行烧录——从 release/ 副本，烧的即发布的）

```bash
python skills/flash/scripts/flash.py --config examples/stm32f103zet6/config.json
```

成功输出（stderr 摘要）：

```
[s9-flash] 烧录中: JLink.exe -device STM32F103ZE -if SWD -speed 4000 -autoconnect 1 -CommandFile flash_cmd.jlink（cwd=...\release）
[s9-flash] 烧录成功（3.2s，verify=O.K.，已复位运行=True）
[s9-flash] 发布清单: ...\release\flash_info.json
```

产物：`App/outputs/s9/flash.log`、`App/outputs/s9/flash_result.json`、
`release/flash_info.json`（发布清单，成败均写）；`state.s9 = done`。

## 3. validate（产物验证 + state 收口）

```bash
python skills/flash/scripts/validate.py --config examples/stm32f103zet6/config.json
```

## 4. 失败路径（阶段 C：Agent analyze）

`flash.py` 退出码 1（如探针未插：`Connecting to J-Link via USB...FAILED`）→
state.s9 保持 `running` → Agent 读 `flash.log` + `flash_result.json`（key_lines），
按 `references/flash_log_parse_rules.md` 四类根因（连接/芯片/固件/工具）产出
`App/outputs/s9/error_analysis.md` → 重跑 `validate.py` 收口 `state.s9 = error`。
**不自动重试、不自动解锁**；恢复后重跑 prepare → flash。

## 5. 常用变体

```bash
# OTA 偏移工程（config: "flash_offset": 0x2000）：hex 自带偏移地址，无需额外参数
# bin 强制（地址 = flash_base + flash_offset，自动计算）：
python skills/flash/scripts/prepare.py --config examples/stm32f103zet6/config.json --format bin

# 显式固件（bin 必须给地址）：
python skills/flash/scripts/flash.py --config examples/stm32f103zet6/config.json \
    --firmware App/outputs/s6/merged.bin --address 0x08000000

# 全片擦除 + 不复位（先擦后烧调试场景）：
python skills/flash/scripts/prepare.py --config examples/stm32f103zet6/config.json --chip-erase --no-reset

# 连接抖动重试：
python skills/flash/scripts/flash.py --config examples/stm32f103zet6/config.json --retry 3
```

## 6. 复烧（生产/现场，无需本框架）

```bash
cd examples/stm32f103zet6/release
JLink.exe -device STM32F103ZE -if SWD -speed 4000 -autoconnect 1 -CommandFile flash_cmd.jlink
```

固件指纹与复烧命令记录在 `release/flash_info.json`（sha256 可离线校验收到的
固件与发布时是否同一份）。
