# PDF 原理图提取原理与置信度说明

> 供 schematic-reader 的 Agent / 维护者理解 `pdf_adapter.py` 的技术路线、
> 置信度模型与已知精度边界。使用者只需关注 `outputs/pdf_review.md` 核对清单。

## 1. 为什么 PDF 只能做到 85~95% 精度

SchDoc / kicad_sch 是结构化源文件：元件、连线、网络标号都是显式对象。
PDF 是排版产物：只剩**矢量图形（线条/矩形/曲线）+ 文字对象（含坐标）**，
"元件"与"连接"必须从几何关系**推断**。推断就有错的可能——这是技术本质，
不是实现缺陷。应对方式：每条连接输出置信度，低置信度进人工核对清单。

## 2. 技术路线（六步）

| 步骤 | 做法 | 关键难点与对策 |
|---|---|---|
| 1. 文字提取 | pdfplumber 优先 / PyMuPDF 兜底，取**字符级**坐标 | 库自带 `extract_words` 在 CAD 导出 PDF 上不可靠（见 §3.1） |
| 2. 图形提取 | 线条/矩形/曲线 + 线宽；线宽 < 0.3pt 的图框线丢弃 | 超长线（> 70% 页面）是图框/分栏线 |
| 3. 元件识别 | 位号正则 + 元件框关联；无框元件按邻域引脚号 | 框关联用互最近（§3.4）；PI 标注兜底（§3.5） |
| 4. 连接推断 | 导线段并查集（端点/T 型/junction 圆点合并）+ 引脚点吸附 + 网络标号 | 引脚点 3pt 内精确命中，8pt 内邻近推断（降置信度） |
| 5. 置信度评估 | 每条连接按判定依据打分（见 §4） | 无标号的自动网络若仅 1 个端点 → 判悬空，不输出 |
| 6. LLM 辅助校验 | 留给 Agent 阶段（`method=llm_assisted`），适配器不调用 LLM | — |

## 3. 关键算法（实战调优经验）

### 3.1 字符级自主聚词（不用库的 word 提取）

CAD 导出 PDF 的文字层有三个陷阱：

1. **紧排字符**：字符框互相微重叠 0.01~0.1pt，`gap < 0`；
   库的词聚类会拆散 `'PA0' → 'P'+'A'+'0'`。
   对策：行内聚词允许 gap ∈ [-3.0, +1.6]pt。
2. **多字号交错**：引脚名（4.6pt）/ 引脚号 / 网络标号（3~4pt Courier）
   x 区间互相重叠。对策：按字号 0.5pt 档**分层**，层内 y 聚行、x 聚词。
3. **双层文本叠加**：同一文字以"完整词层 + 逐字符层"渲染两次
   （如 `U12` size 7.0 与 `U`/`1`/`2` size 6.3 位置重合）。
   对策：多字符词吸收覆盖的单字符词；同文本且中心距 < 3pt 去重。

### 3.2 不对称边缘带（引脚号定位）

引脚号标注在元件框**外**的引线上（实测 5~10pt），框内是引脚名。
框边带判定：框外 12pt / 框内 8pt；距边 < 2pt 的贴边词是网络标号，
排除。框角引脚（距两条边都近）自动 fallback 到次近有效边。

### 3.3 无框元件

电阻/电容等符号无矩形框，按位号 30pt 邻域的**1~2 位**数字词识别引脚
（3 位纯数字如 `104` 是电容 EIA 值码，不是引脚号）。

### 3.4 框关联互最近

电容位号常落在邻近 IC 框 35pt 内。若纯按距离阈值，同一个框会被
两个位号共享，引脚号重复消费、连接成倍虚增。对策：**每个框只归距它
最近的位号**（框内有位号的框优先包含关联）。

### 3.5 PI 标注兜底

部分符号（连接器/红外接收头/稳压器）在 PDF 中没有独立数字引脚号，
唯一线索是紧贴引脚的 `PI<位号><脚号>` 标注词（如 `PIU601` = U6 引脚 1，
正点原子等图纸的标注习惯）。文本自带位号，可靠性强；解析按
`PI+位号` 前缀截断后验尾码（`0\d` 带前导零），避免正则贪婪歧义。

### 3.6 悬空网络过滤

自动命名（无标号）且仅 1 个端点的网络 = 单根引脚线（另一端断线或
电源符号未吸附），无连接价值，按悬空处理：不计入网络、不进置信度
统计，但引脚保留在网表中（`net=null`）——"知道引脚存在但网络未知"
优于丢失引脚。**有标号的网络即使单端点也保留**（真实断线应进核对清单）。

## 4. 置信度模型

| method | 置信度 | 判定依据 |
|---|---|---|
| `pin_name_match` | 0.95 | 引脚名与网络名一致（如引脚 `TXD` 落在网络 `TXD`） |
| `net_label` | 0.90 | 引脚精确落线（≤ 3pt）且该线组有网络标号 |
| `line_intersection` | 0.75 | 引脚精确落线，网络自动命名（`Net<位号>_<脚号>`） |
| `llm_assisted` | Agent 定 | LLM 辅助判断（Agent 阶段补充） |
| （邻近推断） | 0.50 | 引脚未精确落线（距最近导线 ≤ 8pt），按邻近推断 |

分级处理（与需求一致）：

| 置信度 | 处理 |
|---|---|
| ≥ 0.95 | 高可信，直接使用 |
| 0.7 ~ 0.95 | 中可信，S4 阶段重点核对 |
| < 0.7 | 低可信，写入 `outputs/pdf_review.md`，人工审核 |

整体置信度 = 全部连接的算术平均。`< 0.7` 时额外输出全面核对警告。

## 5. 已知精度损失（以正点原子战舰板 5 页 PDF 实测）

| 现象 | 原因 | 影响 |
|---|---|---|
| MCU 电源脚缺失（144 脚识别 120） | 电源脚在 PDF 中只标引脚名（VDD/VSS），无引脚号文字 | 需 S3（手册提取）补全电源脚 |
| 少量垃圾网络名（`COC35` 类） | 'CO' + 位号的层叠词被当网络标号 | 占网络数 < 5%，核对清单可见 |
| 无框小元件（LED/二极管）部分无引脚 | 符号无引脚号文字且无 PI 标注 | 警告列出，人工补 |
| 跨页网络靠同名标号关联 | 各页线组独立，无标号则不合并 | 标号齐全的图纸无影响 |

## 6. 降级策略

| 场景 | 处理 |
|---|---|
| pdfplumber / PyMuPDF 均未安装 | 报错退出，提示 `pip install pdfplumber` |
| 文字层缺失（扫描件，全文档 < 20 词） | 报错退出：需要 OCR，当前不支持 |
| 多页原理图 | 逐页提取；BOM/表格页（无元件框 + 大量文本）自动跳过 |
| 整体置信度 < 0.7 | 警告 + 要求人工全面核对 |
